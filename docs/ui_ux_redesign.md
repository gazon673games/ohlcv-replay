# UX рабочего пространства бектестинга

## Производительность большого графика, 10 октября 2026

Исходная версия — `a7519ef`. На длинной истории обработчик смены диапазона
повторно строил все маркеры, читал CSS для каждого исполнения и форматировал
даже скрытые подписи. При отображении 32 000 свечей на весь экран отрисовка
также обрабатывала свечи, уже неразличимые по отдельности.

Теперь исполнения индексируются при изменении свечей, решений или темы.
Маркеры видимой области выбираются бинарным поиском; их ID сохраняются,
а общий счётчик учитывает всю историю. Подписи вычисляются только для
видимых исполнений, при прежнем ограничении 80 подписей, и повторно используются.
Одинаковая область маркеров не отправляется в библиотеку повторно. OHLC-подсказка
обновляется один раз за кадр и только при изменении свечи или её значений.

Включён штатный `enableConflation` Lightweight Charts с
`conflationThresholdFactor: 1`: объединение касается отрисовки свечей меньше
пикселя, без дополнительного сглаживания. Полная последовательность исходных
свечей, таймфрейм, цены под курсором при увеличении и времена исполнений сохраняются.
Описание параметров: [официальная документация TimeScaleOptions](https://tradingview.github.io/lightweight-charts/docs/api/interfaces/TimeScaleOptions).

Замер в Electron на CSS viewport 3840×2160, DPR 1, с аппаратным ускорением,
сравнивает исходный UI и исправленный на одной детерминированной нагрузке:
32 000 свечей, 8 000 исполнений. Строки таблицы показывают p95 интервала
между кадрами `requestAnimationFrame`, а не гарантированный FPS на других машинах.

| Действие | До, мс | После, мс |
| --- | ---: | ---: |
| Сдвиг увеличенного участка с исполнениями | 30,3 | 6,2 |
| Вся история без маркеров | 66,8 | 12,2 |
| Вся история с 8 000 маркеров | 109,2 | 30,4 |
| Перетаскивание увеличенного участка настоящей мышью Electron | 36,4 | 6,2 |

При движении курсора внутри одной свечи количество изменений DOM-подсказки
снизилось со 122 до 1. В тесте отдельно проверяются сохранение 32 000 свечей
и 8 000 исполнений, реальное перемещение диапазона мышью и точное совпадение
OHLC под курсором с исходной свечой после увеличения. Все 8 000 видимых
маркеров остаются более тяжёлым режимом, чем обычный участок графика.

Воспроизводимый замер: задать `WORKBENCH_SMOKE_PERFORMANCE` как путь JSON-отчёта,
`WORKBENCH_SMOKE_WIDTH` / `WORKBENCH_SMOKE_HEIGHT`, затем выполнить `npm run smoke`
из `ui`. Результаты и изображения находятся в игнорируемой папке
`data/workbench/chart-perf-*.json` / `chart-perf-*.png`; эталонный статический UI
можно указать через `WORKBENCH_SMOKE_STATIC_ROOT`.

Проверки: 27 наборов Node, UX smoke при 1440×900 и 1920×1080, отдельный smoke рынка и
производительности в 4K. Полный UX-сценарий редактора в 4K имеет прежнее
ограничение: короткий тестовый черновик ограничивает прокрутку, а округлённая
граница видимых свечей может отличаться на один бар при изменении панели.
Это воспроизводится на исходном `a7519ef`; 4K-замер выше относится к графику.

## Реархитектура по новому ТЗ TradingView, 10 октября 2026

Исходная версия для сравнения — `cc0f25e`. Изучены DOM, состояние панелей,
Monaco, загрузка каталога, очередь задач, отчёты и обработчики Lightweight Charts.
Ниже приведены результаты нового этапа; дальнейшие разделы описывают
предшествующий редизайн. Палитра, движок и API сохранены.

| Подтверждённая проблема | Решение и приоритет |
| --- | --- |
| Пустой график содержит инструкцию, а загрузка находится справа | P0: непосредственные действия загрузки и выбора инструмента/периода; загрузка блокируется во время работы |
| Верхние переключатели дублируются внутри панели | P0: одна навигация «Данные / Стратегия»; справа заголовок контекста; фокус относится к графику, настройки приложения — к отдельному меню |
| До прогона раскрыт пустой отчёт и выделена область капитала | P0: результаты свернуты; equity создаётся при появлении данных либо инфляционного ориентира |
| Редактор шириной около 440 px требует горизонтальной прокрутки | P1: расширенный режим, отдельная сохраняемая ширина, возвращение к графику, тот же экземпляр Monaco |
| Таблица сделок связана с графиком только в одну сторону | P1: клик по маркеру раскрывает связанную сделку; неоднозначность и отсутствие связи показаны явно |
| В широком окне закрытие панели меняет узкий интервал графика | P1: снято ограничение `maxBarSpacing`, мешавшее сохранить интервал при изменении ширины |
| Проверка готовности данных перекрывает статус отмены/завершения | P0: понятные стадии задачи; готовность следующего запуска — рядом с данными и в подсказке кнопки |
| Асинхронная проверка кода возвращает старые параметры; ошибка стирает поля | P1: черновик параметров сохраняется, изменение во время проверки требует повторной проверки |

График постоянно находится в центре. Правая панель хранит данные, параметры
и код; нижняя — обзор, сделки, решения, диагностику, исследования и историю.
Открытие результатов возвращает обычную ширину редактора. Код, курсор,
прокрутка и инструмент сохраняются при скрытии панелей в сессии. Размеры,
выбранные панели и вкладка записываются в существующие preferences.
Несохранённый исходник не записывается в общий SDK или preferences.
Проверка качества следующего прогона указывает его исходный таймфрейм
и отличается от качества набора отображаемого графика; ID доступен в подсказке.

## Аудит исходного приложения

Приложение уже объединяло график, настройки, редактор и результаты на одной странице.
Синхронизация цены и капитала, отдельные таймфреймы стратегии и графика, bounded preview,
причинная привязка исполнений, проверки качества и явная загрузка данных — полезные
существующие решения. Переписывать их ради сходства с TradingView не требуется.

Обнаруженные проблемы относятся к конкретным сценариям:

| Сценарий | Исходное поведение | Последствие |
| --- | --- | --- |
| Выбор стратегии | Список и редактор ниже графика; смена списка уже открывает стратегию | На небольшом экране приходится прокручивать страницу, чтобы видеть код и рынок |
| Параметры и запуск | Параметры под редактором; капитал и запуск в колонке данных | Действия одной итерации распределены между несколькими областями |
| Просмотр результата | Метрики над графиком, диагностика в закрытом `details`; завершение выбирает скрытую вкладку | Изменение активной вкладки не гарантирует видимость результата |
| Поиск сделки | Сделки после решений в общей вкладке, без поиска и фильтра | Требуется ручная прокрутка; отсутствует переход из строки к графику |
| Открытие старого прогона | Выбор ID и отдельное открытие; капитал отчёта записывается в поле следующего запуска | Просмотр результата изменяет текущие настройки |
| Сравнение | Ручной ввод нескольких ID; таблица и график сравнения в разных вкладках | Легко ошибиться в ID и потерять визуальный контекст сравнения |
| Размеры областей | Фиксированная высота основного графика и постоянно присутствующий редактор | Нельзя временно отдать графику площадь неиспользуемых панелей |
| Изменение индикатора | Повторная загрузка preview очищает `lastReport` | Настройка отображения лишает пользователя контекста результата |
| Повторный запуск | Обработчик запуска без блокировки на период подготовки данных | Быстрые повторные нажатия могут запустить несколько конкурирующих операций |

## Архитектура и приоритеты

### P0: Постоянный график и панели вокруг него

Центральная область содержит цену и капитал с общей временной шкалой. Боковая панель
переключает данные и стратегию. В панели стратегии параметры расположены перед кодом,
а существующие действия загрузки, сохранения, проверки и редактирования SDK доступны
рядом с редактором. Нижние вкладки открываются независимо от боковой панели.

Это решает прокрутку между редактором и рынком. Референс — закреплённый редактор
TradingView; общая панель данных и стратегии адаптирует его к бектестингу.
Переключение скрывает существующие DOM-области и сохраняет редактор, поля, фильтры
и результат. Разделители меняют ширину и высоту мышью или стрелками клавиатуры.
При изменении геометрии восстанавливается видимый диапазон свечей. Последующий явный
переход пользователя к сделке или другому диапазону имеет приоритет над восстановлением.

В режиме фокуса панели временно скрываются. Повторное нажатие или Esc возвращает
предыдущую раскладку. В узком окне боковая панель становится закрываемой панелью поверх
графика; на мобильной ширине страница допускает вертикальную прокрутку.

### P0: Явный цикл параметров, запуска и результата

Запуск и отмена находятся в верхней панели, статус — в постоянной нижней строке.
Успешный запуск открывает «Обзор»: метрики, ID и контекст результата, сохранённые
параметры стратегии, портфеля и исполнения. Текущие поля относятся к следующему запуску.
Просмотр старого результата сохраняет введённый капитал и код.

Блокировка начинается до асинхронной подготовки данных. Повторный запуск, sweep
или загрузка графика не перекрывают активную операцию. Отмена остаётся запросом,
пока очередь не подтвердит терминальное состояние; отменённый прогон не отображается
как ошибка. История сохраняется сервером как прежде. При нескольких запросах открытия
старых отчётов результат последнего выбора имеет приоритет.

Референс — отчёт выбранной стратегии под графиком. Явная очередь, защита от повторного
запуска и независимые настройки следующего прогона — адаптация для Workbench.

### P0: Журнал связан с рынком

«Сделки» отделены от «Решений». Журнал поддерживает поиск по отображаемым значениям
(номер, дата, направление), фильтр направления и порядок по времени входа. Сначала
показываются новые сделки. Фильтрация не меняет исходные таблицы отчёта.

Нажатие строки или кнопки номера выделяет сделку, показывает интервал с запасом свечей
и добавляет подписи входа и выхода. Подтверждённые маркеры исполнений сохраняются.
Референс — переход из TradingView Trades к соответствующему бару; показ всего интервала
вход–выход одним действием — наше предложение.

Привязка использует существующие правила исполнения: исполнение по закрытию относится
к предыдущей свече, а на обзорной серии — к содержащей свече. Точки не переносятся
в будущее. Если обязательные timestamps или свечи недоступны, появляется сообщение,
а диапазон графика сохраняется. Это особенно важно для ограниченной серии архивного
отчёта: дополнительные свечи не выдумываются и не подгружаются скрыто.

### P1: Управление рядом с графиком

Выбор инструмента автоматически открывает сохранённые цены для совместимого
таймфрейма. Изменение периода запускает такой же поиск. При полном покрытии свечи
не скачиваются; при частичном сохранённые цены остаются видимыми, пока адаптер
догружает недостающие интервалы. Библиотека в дополнительных настройках показывает
данные выбранного рынка; ручной выбор набора не требуется. Кнопка «Обновить график»
повторяет загрузку текущего выбора. Режим «Автоматически: кэш и догрузка» используется
по умолчанию; офлайн и принудительное обновление доступны в дополнительных настройках.

Начальный период берётся из сохранённых данных, совместимых с графиком. Если их нет,
используются последние 90 дней. Фоновое уточнение доступной истории не расширяет этот
период; пользователь может изменить даты. Смена инструмента отменяет начатую загрузку,
а запоздавший ответ сохраняется только как данные и не заменяет выбранный график.
Отображение цен сохраняет независимые требования качества данных для запуска стратегии.

Адаптер MOEX хранит успешные запросы свечей в локальном кэше и объединяет покрытие
нескольких снимков. При расширении периода скачиваются отсутствующие интервалы.
Текущий день может быть незавершённым и проверяется отдельно. Экспирации старых
контрактов берутся из явных `LSTTRADE` / `LSTDELDATE` спецификаций MOEX ISS,
сохраняются в кэше, а исходный ответ и его SHA-256 включаются в аудит ряда.
Границы файлов свечей не используются как даты экспирации.

Дополнительные проверки: 23 набора Node-тестов, 70 backend-тестов и Electron smoke
с автоматическим открытием CNY (358 свечей, 0 скачиваний). В реальной локальной истории
CR офлайн загружены 1562 свечи за 14–16 сентября 2022 года с переходом CRU2 → CRZ2
после последнего торгового дня первого контракта.

Таймфрейм отображения, индикаторы, приближение/отдаление, автошкала цены, перекрестие,
весь период и помощь расположены над графиком. Правый клик открывает основные действия
и переход к сделкам. Перекрестие дополняется OHLC и временем свечи.

Сохраняются стандартные действия Lightweight Charts: колесо для масштаба, перетаскивание
для перемещения и управление шкалами. Кнопка автошкалы возвращает автоматический подбор
цены; «Весь период» восстанавливает временной охват. На активном графике +/− меняют
масштаб, стрелки перемещают окно, Home показывает весь период. Эти сочетания — наш выбор,
а не утверждение о совпадении с TradingView.

Перезагрузка preview для индикаторов и совместимого таймфрейма сохраняет выбранный
отчёт, капитал, исполнения и диапазон. Если выбранный таймфрейм требует другого источника,
UI сообщает о необходимости загрузить график. Стратегия сохраняет собственный timeframe;
из более крупных свечей не синтезируются мелкие. Масштабирование не меняет данные серии.

### P1: История и сравнение в одной области

Завершённый прогон открывается нажатием его ID в истории. Флажки собирают список
для существующего `/api/compare`; ручной ввод остаётся доступен. Повторяющиеся ID
исключаются, требуется минимум два разных прогона. Таблица и график сравнения
показываются в одной вкладке «Прогоны и задачи».

Это решает ошибки ручного ввода и разделение результатов сравнения. Выбор флажками
и сохранённая история — наше предложение для Workbench. Незавершённые и ошибочные
прогоны остаются видимыми в истории, но не предлагаются флажком для сравнения отчётов.
Все значения метрик и equity приходят из существующего API, второй расчёт PnL не добавлен.

## Спецификация основных взаимодействий

| Действие | Реакция | Изменение состояния | Результат |
| --- | --- | --- | --- |
| Выбрать данные / стратегию | Открывается соответствующая боковая область | Активная панель и видимость записываются в настройки | График и другой контекст доступны без перехода страницы |
| Закрыть панель | График получает её ширину | Содержимое панели остаётся в DOM | Код и параметры доступны при повторном открытии |
| Передвинуть разделитель / нажать стрелку на нём | Меняется размер области | Размер сохраняется; viewport восстанавливается после изменения геометрии | Раскладка соответствует задаче пользователя |
| Фокус / Esc | Панели скрываются / возвращаются | Временный режим сохраняет предыдущую раскладку | Можно исследовать график и вернуться к настройкам |
| Изменить параметр и запустить | Подготовка данных, очередь, прогресс | Один активный запуск; сервер замораживает request и исходники по прежнему контракту | Результат открывается в обзоре |
| Отменить | Показано ожидание отмены, polling продолжается | Очередь подтверждает cancelled, блокировка снимается | Можно снова запустить стратегию |
| Выбрать сделку | Выделение строки и точки входа/выхода | Меняется только viewport и выбранная строка | Результат исследуется в рыночном контексте |
| Выбрать сделку без данных | Сообщение о недоступных свечах | Viewport сохраняется | Ограничение данных видно пользователю |
| Открыть другой отчёт | Показаны его рынок, метрики, сделки и сохранённые настройки | Меняется выбранный report; поля следующего запуска сохраняются | Историю можно исследовать без порчи текущего черновика |
| Изменить индикатор / совместимый timeframe | Перезагружается display preview | Report, equity, исполнения и viewport сохраняются | Изменение отображения не сбрасывает анализ |
| Отметить два прогона и сравнить | Открыты таблица и график сравнения | Список уникальных ID отправляется существующему API | Сравнение без переписывания ID |
| Перезапустить приложение | Восстановлены панели, вкладки, размеры | Загружаются сохранённые предпочтения | Рабочее пространство предсказуемо |

Восстановление раскладки не запускает бектест, не открывает старый отчёт и не публикует
черновик стратегии. Сохранение стратегии и «Сохранить общий файл SDK» сохраняют
разные существующие значения; история исходников, revision conflict checks и снимки
для очереди не изменены.

## Сравнение сценариев до и после

Числа ниже относятся к явным действиям интерфейса после подготовки исходных данных.
Прокрутка указана отдельно, поскольку её объём зависит от размера окна. Время выполнения
пользователем не измерялось; выводы о скорости основаны на устранённых переходах.

| Сценарий | Было | Стало |
| --- | --- | --- |
| Увидеть отчёт после запуска | Раскрыть результаты и найти активную вкладку | Обзор открывается автоматически |
| Открыть журнал | Раскрыть результаты → «Действия» → прокрутить решения | «Сделки»: одно нажатие |
| Найти сделку | Ручная прокрутка таблицы | Поиск / фильтр, затем одно нажатие строки |
| Перейти к сделке на графике | Готового действия нет | Одно нажатие строки, без ухода из журнала |
| Сменить параметры и исследовать новый результат | Прокрутка редактора, колонки запуска и графика | Боковая стратегия → параметры → постоянная кнопка запуска → автоматический обзор |
| Открыть прогон из истории | Выбрать в списке и нажать «Открыть»: два действия | Нажать ID: одно действие |
| Сравнить два прогона | Вкладка истории, ручной ввод ID, сравнение; график в диагностике | Два флажка и сравнение; таблица и график вместе |
| Освободить площадь для графика | Изменения размеров не предусмотрены | Закрыть нужную панель или одно нажатие фокуса |
| Закрыть/открыть редактор | Отдельного действия нет | Одно нажатие с сохранением черновика и масштаба |
| Перезагрузить интерфейс | Сохранялись тема и индикаторы | Дополнительно сохраняются вкладки, видимость и размеры панелей |

## Проверки

- `npm run test:chart-data`: 22 набора проверок UI, включая новое покрытие перехода
  сделки к свечам, исполнения по закрытию и недопустимого создания мелких свечей.
- `WORKBENCH_SMOKE_UX=1 npm run smoke`: браузерные сценарии журнал–график,
  сохранения черновика и капитала, изменения размеров, фокуса, сравнения, повторного
  нажатия запуска, отмены, следующего запуска и восстановления раскладки после reload.
- Smoke в светлой и Grimdark-темах при 1440×1000, в тёмной теме и английском языке
  при 900×800; сохранение темы и настроек индикаторов при reload.
- Smoke на сохранённых данных: 358 свечей до и после zoom, число preview-запросов
  не меняется при zoom; изменение периодов индикаторов сохраняет диапазон. Включены
  SMA, EMA, Bollinger, объём и инфляционные ориентиры.
- 24 backend-теста из `test_workbench.py`, `test_workbench_report.py` и
  `test_workbench_platform.py` прошли. Backend source не изменялся.
- Изменённые JavaScript-файлы не превышают 300 физических строк. Генерируемые
  vendor/build/dist и локальные datasets в коммит не входят.

В данном окружении обычный запуск Electron из sandbox останавливался на проверке
Windows AppContainer ACL. Smoke выполнялся с изолированной копией Electron во
временном каталоге и `ELECTRON_OVERRIDE_DIST_PATH`, вне sandbox процесса. Production
launcher и режим безопасности Electron не изменены. Smoke теперь явно завершает
свой backend и при успехе, и при ошибке, чтобы не оставлять тестовые серверы.

Скриншоты проверок находятся в игнорируемом `data/workbench/`: `ui-smoke.png`,
`ui-ux-grimdark.png`, `ui-ux-900.png`, `ui-ux-market.png`.
